# 1.21.6 课堂事件与自动作答设计

## 目标

将雨课堂助手从“只依赖当前页面课堂”扩展为“监听当前账号所有正在上课的课堂”，并修复发布提醒、弹幕跟发、截止后作答和自动跳转的实际行为。版本统一提升为 `1.21.6`。

## 范围与不变条件

- 监听范围是当前账号接口返回的 `status === 1` 课堂；未开始或已结束的选课不建立后台监听。
- 桌面专用运行模式保持不变；`/m/v2` 路由守卫不回退为手机版运行时。
- 不新增第三方依赖，继续使用 ES Module、Rollup、Tampermonkey API 和 Node `node:test`。
- 自动作答与强制补交继续保持用户显式开关；强制补交不能绕过服务器权限、课程状态或服务端拒绝。
- 后台课堂只接收提醒和状态事件；弹幕跟发只允许在当前可见课堂的原生发送控件上执行，避免把一堂课的弹幕发送到另一堂课。

## 根因结论

1. 发布事件由 WebSocket 分发时虽然暂时带有 `lessonId`，但 `actions.onPublishEvent` 没有接收该上下文；发布去重键也没有课堂维度，且没有可靠的当前课件标识，因此无法实现跨课堂提醒和“当前课件不提醒”。
2. 自动跟发当前只统计“同一文本出现 3 次”，发送成功只表示调用了 DOM `click()`，没有验证雨课堂实际发出了发送帧；测试也只验证了点击，不验证网络发送。
3. `submitAnswer` 已有 `/retry` 分支，但自动答题入口在截止时间后直接返回，导致强制补交路径不可达。
4. 自动进入课堂只选择列表中的第一项，并且缺少过期课堂清理和用户操作仲裁；旧 WebSocket 关闭后也没有从仓库清除连接状态。

## 总体架构

### 课堂状态

在 `repo` 中维护每个课堂的独立状态：连接、token、最后一次活动时间、当前活动标记和自动答题策略。`getOnLesson()` 的结果是事实来源；每轮同步时建立新增活动课堂的连接，并关闭或清理不再活动的连接。事件处理器必须始终接收 `lessonId`，题目、发布提醒和课程结束提醒都使用该上下文。

### 发布提醒

发布解析器输出统一事件：`category`、`lessonId`、`entityId`、`presentationId`、`dedupeKey`、标题和详情。提醒路由按下列规则决定：

- `event.lessonId !== currentLessonId`：提醒；
- 同一课堂但发布实体不是当前正在查看的课件：提醒；
- 同一课堂且 `event.presentationId === currentPresentationId`：不提醒；
- 无法确认当前课件时不静默发布事件，仍提醒，并在日志中标记上下文不完整。

去重键至少包含事件类别、课堂 ID 和发布实体 ID，避免相同 ID 在不同课堂之间互相抑制。

### 弹幕跟发

默认检测窗口为“最近 7 条非空弹幕在 30 秒内”。达到 7 条即计算窗口内出现频率最高的文本；频率相同取最近一次出现的文本。每 60 秒为一个跟发轮次，每轮最多 2 条，并且同一文本每轮只跟发一次。跟发只在当前页面课堂执行。

发送器在点击原生发送按钮前登记待确认文本；WebSocket 发送拦截器识别雨课堂的弹幕发送帧后确认。确认超时或明确控件/网络失败时，返回失败原因并记录日志，不把 DOM 点击误报为已发送。

### 自动作答

将作答流程拆为：排队、取图、快速模型作答、提交、精确模型验证、必要时重试提交。用户设置时间点后形成时间窗口 `[point - 60s, point + 600s]`；题目进入窗口时使用快速 Profile，窗口外使用正常 Profile。快速答案先提交以满足时效，再由精确 Profile 验证；验证发现答案不同且题目允许重交时使用 `/retry` 提交修正答案。验证失败不会盲目重复提交，最多执行一次修正。

截止后若用户开启“自动强制补交”，流程允许进入 `/retry`；普通自动作答仍受原有设置控制。无 API Key 时继续沿用本地默认答案，但强制补交必须明确标记为 retry 路由。

### 自动跳转

自动跳转器维护一次用户操作仲裁窗口：发现最新活动课堂后先等待 10 秒；窗口内有点击、键盘、滚动或历史路由操作则放弃自动跳转；窗口结束且用户没有操作时才跳到最新活动课堂。最新课堂按接口提供的时间字段排序，字段缺失时保持接口顺序，不使用“没有 `status === 1` 就回退到任意课堂”的逻辑。

## 配置接口

新增配置保持向后兼容：

- `autoForceRetry`：是否允许自动作答在截止后调用 `/retry`，默认 `false`。
- `fastAnswerProfileId`：时效窗口内使用的快速 Profile，默认空表示使用当前 Profile。
- `verifyAnswerProfileId`：提交后验证使用的精确 Profile，默认空表示不做二次验证。
- `answerPriorityWindows`：用户时间点及窗口规则，默认空数组；每项为 `{ at: "HH:mm", beforeMs: 60000, afterMs: 600000 }`。
- `answerVerification`：是否启用精确模型验证，默认 `false`。
- `answerVerificationDelay`：快速提交后等待验证的毫秒数，默认 `0`。

快速 Profile 只在配置完整且对应模型可调用时使用；否则记录回退原因并使用当前 Profile。所有 API 配置继续保存在现有本地配置中，不新增明文日志输出。

## 错误处理与安全边界

- WebSocket 关闭、错误或认证失败必须清理课堂连接状态，并允许下一轮同步重新连接。
- 任何课堂 token、Authorization、API Key 和完整 hello 帧不得写入普通日志；调试日志只输出布尔状态、课堂 ID 和非敏感事件摘要。
- 发送确认使用有界超时；超时不重试点击，避免重复发送刷屏。
- `/retry` 失败时保留原始答案状态和失败原因，UI 提供明确反馈；不将“请求已发出”视为“服务器已接受”。
- 多课堂状态按 `lessonId` 隔离；后台课堂不会改变前台课件、幻灯片或弹幕发送目标。

## 测试策略

- 纯函数测试：发布事件上下文与过滤、活动课堂同步、弹幕 7/30 秒统计、时间窗口选择、答案路由选择、跳转仲裁。
- 集成测试：实时分发把 `lessonId` 传入各处理器；WebSocket 关闭清理；发送帧确认；超时与验证失败路径。
- 回归测试：保留现有 68 项测试，补充跨课堂、当前课件抑制、强制补交、模型回退和用户操作优先级。
- 构建验证：`npm test`、`npm run build`、产物与 `release/ykt-helper-1216.user.js` 完全一致，并检查用户脚本头部为 `1.21.6`。
